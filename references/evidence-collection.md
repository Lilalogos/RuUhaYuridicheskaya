# Сбор улик: фазы A/B/C и квирки порталов

Полный регламент — [`evidence/CLAUDE.md`](../evidence/CLAUDE.md) (правила §0, сценарии §1, где искать §2, форматы §3–§7, формулы запуска §8, критерии неудачи §9). Здесь — выжимка и то, чего в регламенте нет: что выяснилось на прогонах 2026-10-04.

## Неизменяемые правила (§0)

1. **Cite-or-abstain.** Поле реестра заполняется только из документа, лежащего в `evidence/` (PDF с текстовым слоем или сохранённая страница). Нет документа — `Не установлено по приложенным источникам`. Ничего по памяти, ничего «по новостям».
2. **Первичка и наводки — разные папки.** Акт суда / решение УФАС / постановление Роспотребнадзора → `enforcement/`. Новость, пост, дайджест, пресс-релиз без текста акта → `leads/`. Наводка никогда не становится источником поля.
3. **Никаких оплат.** Довести до экрана перед оплатой и остановиться. Карты, подписки, «Оплатить» — нет.
4. **Вход, капча, телефон, СМС — только человек (Виталий).** Увидел — СТОП.
5. **Агент не классифицирует.** Он фиксирует URL, время, экран, цитату со страницей. Ожидаемые паттерны, факты, класс gold/clean — разметка Виталия. В записях реестра исходов `linked_patterns_or_practices` — предварительная посадка куратора, не вывод агента.
6. **Ничего не замазывать и не кадрировать.** Персональные данные в кадре решает Виталий при разметке.
7. **Не выдумывать URL.** Нет карточки — «карточка не найдена» + URL поиска.
8. **Один сценарий за прогон.** Побочные находки — в журнал, раздел «Отложено».
9. **Никаких оценочных слов** в `agent_note` и журналах («навязывание», «нарушение», «обман» допустимы только внутри поисковых запросов и дословных цитат).

## Форматы (§3–§7)

```
evidence/
  enforcement/<ГГГГ>-<орган>-<номер>/  source.pdf  source.sha256  source.url.txt  meta.yml  quotes.md
  leads/<сценарий>/<ГГГГММДД>-<домен>.md
  captures/<сценарий>-<домен>-<ГГГГММДД>/  NN-<шаг>.png  NN-<шаг>.pdf  capture-log.json  manifest-draft.md  SHA256SUMS.txt
  runs/<ГГГГММДД>-<сценарий>-<фаза>.md
```

Текстовый слой каждого PDF обязателен: `pdffonts source.pdf` показывает шрифты, `pdftotext source.pdf - | head` читается. Без слоя → `source.scan.pdf`, `text_layer: false`, цитат из него нет.

`meta.yml`: каждое значение со страницей; `act_type` из списка (решение суда | постановление | решение УФАС | предписание) — для определений апелляции/кассации выбиралось ближайшее и помечалось в `notes` (ждёт правки Виталия). `quotes.md`: `**стр. N** — «дословно» (позиция стороны / изложение)`, сверка с `pdftotext`.

## Фазы

- **A — поиск актов (один сценарий):** доступ к порталам → 3–5 запросов с журналом → для каждой карточки убедиться, что это акт, скачать/напечатать PDF, sha256, текстовый слой → meta.yml + quotes.md → **СТОП**: список актов и наводок, выбор сайтов для B.
- **B — съёмка по акту (один сайт):** Chrome, 1440×900 (фактически было 1708×832, DPR 2), русский интерфейс, GIF → маршрут из `interface_facts` акта или стандартный (главная → товар → корзина → шаги до экрана перед оплатой) → PNG + capture-log на каждом шаге → на ключевых экранах PDF (Ctrl+P Виталий, либо печать DOM агентом — вёрстка упрощена) → для G6 повтор через 15 минут и после перезагрузки (`-2`) → для G1/G2 снять галочку и зафиксировать реакцию → если паттерна нет, дописать серию до конца (clean-кандидат) → sha256, manifest-draft с пустыми полями разметки.
- **C — отчёт:** что искали / нашли / не нашли и почему / отложено / сколько первички и наводок / СТОПы / сверка с §9.

## Как акт попадает в базу

1. Папка в `evidence/enforcement/` по §3–§4 (агент).
2. Посадка в `OVERLAY` скрипта [`scripts/build_evidence_capsules.py`](../scripts/build_evidence_capsules.py): posture, finality, `benchmark_eligibility`, нормы базы, предварительные паттерны, pinpoint, сопоставимость, ограничения (куратор).
3. `python3 -B scripts/build_evidence_capsules.py` → капсула + запись исхода + `eligible_outcome_ids` у материальных норм.
4. `python3 -B scripts/build_references.py` → справочники; `python3 -B scripts/refresh_release.py` → профиль релиза и контрольные суммы.
5. `cd applaw && python3 -B scripts/validate_release.py --kb .` → PASS 15/15 обязателен.

Пригодность как ориентира (`eligible_*`) ставится только если финальность следует из приложенного текста (например, кассационное определение, оставившее акты без изменения). Карточка дела на сайте суда — не текст акта; хотите поднять запись до eligible — приложите печать карточки или акт вышестоящей инстанции и перенесите в `finality` со страницей.

## Тексты законов и карточки судов (добавлено прогоном 2026-10-04)

- **Тексты законов** — `evidence/law/<slug>/` (`source.pdf` с текстовым слоем, `source.url.txt`, `source.sha256`, `meta.yml`); список — `evidence/law/SOURCES.tsv`, индекс — `evidence/law/INDEX.md`. Источник — страницы КонсультантПлюс (publication.pravo.gov.ru с этой машины недоступен). Корневые страницы амендмент-законов отдают только оглавление — для них `scripts/fetch_laws.py` печатает постатейные страницы (`EXPAND`). Печать — `scripts/print_pdf.sh` (Chrome headless с принудительным завершением).
- **Карточки дел судов** — `card.pdf`/`card.html`/`card.sha256`/`card.url.txt` в папке акта (`scripts/snapshot_card.py <url> <папка>`): текст страницы, включая скрытые вкладки «Движение дела» и «Обжалование». Это «сохранённая страница», не текст акта — годится для `finality` в реестре исходов и для `notes` в meta.yml, но не для `interface_facts`.
- **База решений ФАС** — поиск `https://br.fas.gov.ru/?type=2&text=<запрос>` (curl отдаёт HTML со ссылками `/to/<ufas>/<id>/`), печать карточки документа — `scripts/fetch_fas_batch.sh`; стр. 1 PDF — шапка сайта, текст акта со стр. 2.
