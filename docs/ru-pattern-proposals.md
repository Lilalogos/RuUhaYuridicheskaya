# Предложения новых паттернов под RU-нормы (P-01…P-05)

Статус (обновление 2026-10-01): **P-01, P-02, P-03 и P-05 реализованы** нормами и паттернами по указанию оператора «дополни что ещё нету» (personalized-price-discrimination, foreign-sso-only, missing-recsys-notice, cookie-single-accept); **P-04 остаётся предложением** и ждёт отдельного решения — он разблокирует ru-289fz-platform. Исходный текст предложений ниже сохранён для истории.

Статус исходный: **предложения** — в `taxonomy/patterns.yml` ничего не добавлено (правило промпта: новые паттерны только отдельным списком с обоснованием и примером экрана). Принятие любого пункта = отдельный мини-батч: паттерн + гейты + маршрут + при необходимости процедурный спутник; id существующих паттернов не меняются.

---

## P-01 `personalized-price-discrimination` — персональная цена «своему/новому»

**Family/stage:** pricing / plan-selection, checkout.
**Зачем:** ГК РФ ст. 426 — публичный договор: цена и условия одинаковы для потребителей одной категории; «Персональная цена для „лояльного“ или „нового“ клиента — риск нарушения публичного договора» (PDF, стр. 27, 31). Ни один из 68 паттернов не ловит разницу цен как таковую.
**Detection cues (EN + RU-строки):** the same SKU or plan shows different prices tied to the viewer's identity or history; badges like «Цена для вас», «Персональная скидка только для новых», price changes after login; a comparison screenshot or an on-screen admission («для новых пользователей — 199 ₽»).
**Avoid (ловушки FP):** объявленные программы лояльности с опубликованными правилами (PDF: «скидки только по объявленным программам»); промокоды, введённые пользователем; региональные цены с явной географией; A/B на не-ценовых элементах.
**Candidate norms/gates:** material `ru-gk-426` (батч 2); required: `ru-consumer-b2c-transaction`, новый `ru-identity-linked-price-difference-shown` (разница видна на экране/в сравнении, не домыслена); disqualifying: новый `ru-published-loyalty-program-rules-linked`.
**Пример экрана (словесный макет):** карточка тарифа «Про — 299 ₽/мес», ниже плашка «Персональная цена для вашего аккаунта. Для новых пользователей — 199 ₽/мес»; в шапке виден логин.
**Процедурный спутник:** нет в PDF (понуждение к договору/убытки — гражданско-правовое, стр. 27); не заводится.

## P-02 `non-compliant-sso-only` — вход только через запрещённые SSO

**Family/stage:** consent/access / registration, pre-checkout.
**Зачем:** 149-ФЗ ст. 10 (ред. 406-ФЗ): авторизация россиян — только четырьмя российскими способами; «Кнопка „Войти через Google/Apple“ — запрещено, КоАП 13.55» (PDF, стр. 16, 31; штрафы юрлицам до 700 тыс./1,4 млн — стр. 16).
**Detection cues:** the login/registration step offers «Войти через Google», «Sign in with Apple», «Continue with Facebook» as the only or default path; отсутствуют телефон РФ/ЕСИА/VK ID/Яндекс ID/Сбер ID.
**Avoid:** иностранные SSO рядом с работающими российскими способами (состав — способ авторизации как таковой, но чекер фиксирует именно наличие/единственность: юрвывод о «наличии рядом» требует текста нормы — батч 2); продукт явно не для РФ-аудитории (рыночный скоуп не RU — гейт юрисдикции).
**Candidate norms/gates:** material `ru-149fz-10-auth` (батч 2, по стр. 16 PDF); required: `ru-ru-market-targeting-declared` (целевой рынок RU подтверждён оператором, не выведен из языка), новый `ru-foreign-sso-offered`; disqualifying: новый `ru-russian-auth-method-available` — применимость «только/рядом» фиксируется условием маршрута после сверки текста 406-ФЗ (shopping list).
**Пример экрана:** модал «Вход» с двумя кнопками — «Continue with Google», «Sign in with Apple»; ни телефона, ни Госуслуг.
**Процедурный спутник:** `ru-koap-13-55` (стр. 16, 59; дата начала действия состава — «лето 2026, проверить», стр. 64 → effective-date-гейт).

## P-03 `missing-recsys-notice` — лента без уведомления о рекомендательных технологиях

**Family/stage:** disclosure / storefront, product-feed (pre-checkout).
**Зачем:** 149-ФЗ ст. 10.2-2 (408-ФЗ): плашка + правила применения; «Лента без уведомления — нарушение, КоАП 13.56, до 700 тыс. ₽» (PDF, стр. 16, 20, 31).
**Detection cues:** персонализированные блоки («Вам может понравиться», «Подобрано для вас», умная сортировка) при отсутствии на сайте/в приложении плашки «применяются рекомендательные технологии» и ссылки на правила.
**Avoid:** редакционные подборки без персонализации; наличие плашки в футере (чекер видит не все страницы — отсутствие на скриншоте ≠ отсутствие на ресурсе → факт по умолчанию unknown, вывод условный); право «отключить ленту» закон не требует (стр. 20) — его отсутствие не нарушение.
**Candidate norms/gates:** material `ru-149fz-10-2-2` (батч 2); required: новый `ru-personalized-feed-present`, новый `ru-recsys-notice-absent-on-shown-screens` (строго по показанным экранам); disqualifying: новый `ru-recsys-notice-visible`.
**Пример экрана:** главная магазина с каруселью «Подобрано для вас» и «Вы смотрели»; в футере скриншота — только контакты, плашки нет.
**Процедурный спутник:** `ru-koap-13-56` (стр. 16, 59; effective-date «лето 2026, проверить»).

## P-04 `marketplace-sort-override` — подмена выбранной пользователем сортировки

**Family/stage:** manipulation / listing, pre-checkout.
**Зачем:** 289-ФЗ (в силе 01.10.2026): «Сортировка: выбранный пользователем критерий не подменяется; платные инструменты продвижения — на равных условиях» (PDF, стр. 28, 31). Норма `ru-289fz-platform` уже заведена (ответ № 6) и ждёт именно этот паттерн для достижимости.
**Detection cues:** выбрано «Сначала дешевле»/«По рейтингу», но верх выдачи занимают карточки с пометками продвижения или без неё, нарушающие выбранный порядок; значения сортировки видимо противоречат порядку (цены 500→300→900 при «дешевле»); mapped RU cues: «Сначала дешёвые», «По популярности», бейдж «Промо»/«Спонсировано».
**Avoid:** промо-позиции, явно вынесенные в отдельный помеченный блок над результатами с маркировкой «Реклама» + erid (это зона 38-ФЗ 18.1, паттерн «реклама как органика» — другой состав); закреплённые системные строки («Вы недавно смотрели»).
**Candidate norms/gates:** material `ru-289fz-platform` (есть); required: `ru-consumer-b2c-transaction`, новый `ru-intermediary-platform-context` (признаки маркетплейса-посредника на экране), новый `ru-user-selected-sort-visibly-overridden`, новый effective-date-гейт `ru-289fz-in-force` (дата оценки ≥ 01.10.2026; наличие платформы в реестре с экрана не видно → отдельный unknown-факт); disqualifying: новый `ru-promoted-rows-clearly-separated-and-labeled`.
**Пример экрана:** выдача маркетплейса, контрол «Сортировка: сначала дешевле» активен; первые три карточки — 1 240 ₽, 980 ₽, 2 100 ₽, у первой бейдж «Промо», далее 310 ₽, 345 ₽…
**Процедурный спутник:** нет — «штрафы платформ — отдельный закон 2026 г. (проверить)» (стр. 28); до приложенного текста не заводится.

## P-05 `cookie-single-accept` — cookie-баннер с единственной кнопкой «Принять»

**Family/stage:** consent / entry, pre-checkout.
**Зачем:** 152-ФЗ ст. 9: добровольность согласия; «Cookie-баннер с единственной кнопкой „Принять“ — риск: согласие не добровольное; норма прямо не описана» (PDF, стр. 15, 31). Это **риск-паттерн**: отчётный потолок — ниже нарушения, формулировка «risk», не «violation».
**Detection cues:** баннер с одной активной кнопкой «Принять»/«ОК» без «Отклонить»/настроек; формула «Продолжая пользоваться сайтом, вы соглашаетесь…» как единственный механизм.
**Avoid:** баннер с равнозначными «Принять»/«Отклонить»; чисто информационное уведомление без слова «соглашаетесь» и без привязки согласия к действию.
**Candidate norms/gates:** material `ru-152fz-9` (батч 2); required: `ru-consumer-b2c-transaction`, новый `ru-cookie-banner-accept-only`; disqualifying: новый `ru-equal-decline-option-present`. Маршрут обязан нести cap-условие: вывод не выше «risk» — PDF прямо фиксирует отсутствие прямой нормы.
**Пример экрана:** нижний баннер «Мы используем cookie. Продолжая, вы соглашаетесь с политикой» и одна жёлтая кнопка «Принять».
**Процедурный спутник:** `ru-koap-13-11` — только после батча 2 (152-ФЗ) и только как условный.
