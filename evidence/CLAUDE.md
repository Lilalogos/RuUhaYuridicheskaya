# evidence/ — сбор доказательной базы для AppLaw-RU

Эта папка — рабочее место Claude Code для двух задач:
(A) найти и заархивировать решения судов, Роспотребнадзора и ФАС по тёмным паттернам
в российских интерфейсах; (B) по этим решениям снять серии экранов для gold/clean.

Запуск: `claude --chrome` из корня репозитория. Один прогон = одна фаза и один сценарий.
Человек в контуре: Виталий. Всё, что помечено «СТОП», ждёт его ответа.

---

## 0. Правила, которые нельзя нарушать

1. **Cite-or-abstain.** Любое поле заполняется только из документа, лежащего в этой папке
   (PDF с текстовым слоем или сохранённая страница). Нет документа — поле получает
   значение `Не установлено по приложенным источникам`. Ничего не дописывать по памяти,
   не «уточнять» по новостям, не выводить номер дела из косвенных признаков.
2. **Первичка и наводки — разные папки.** Судебный акт, решение УФАС, постановление
   Роспотребнадзора — это первичка (`enforcement/`). Новость, пост на vc.ru, дайджест,
   пресс-релиз без текста акта — это наводка (`leads/`). Наводка никогда не становится
   источником поля в реестре.
3. **Никаких оплат.** Не вводить данные карт, не подтверждать покупки, не оформлять
   подписки, не нажимать «Оплатить». Довести до экрана перед оплатой и остановиться.
4. **Вход, капча, телефон, СМС — только человек.** Увидел форму входа или капчу —
   СТОП, позвать Виталия, после его «готово» продолжать.
5. **Не классифицировать.** Агент фиксирует: URL, время, экран, цитату со страницей.
   Ожидаемые паттерны, факты, маршрут, класс в манифесте размечает Виталий.
6. **Ничего не замазывать и не кадрировать.** Снимать экран целиком. Персональные данные
   не фиксировать специально, но и не вырезать из кадра — это решает Виталий при разметке.
7. **Не выдумывать URL.** Если точная карточка акта не найдена — писать «карточка не
   найдена» и давать URL страницы поиска, с которой искали.
8. **Один сценарий за прогон**, независимо от того, сколько ещё интересного встретилось.
   Побочные находки — в `runs/<дата>-run.md`, раздел «Отложено».

|-----|----------|--------------------------|-------------------------------|
| G1 | Предвыбранная платная допуслуга | ЗоЗПП ст. 16 (п. 2, 3.1); КоАП 14.8 (состав о навязывании, введён 505-ФЗ) | «автоматически проставлялась отметка», «предустановленная галочка», «согласие по умолчанию», «навязывание дополнительной услуги», «страхование на время полёта» |

| G3 | Скрытая полная стоимость | ЗоЗПП ст. 10; 38-ФЗ ст. 5 ч. 3 п. 4 (цена) | «не доведена информация о полной стоимости», «сервисный сбор», «итоговая цена отличалась» |
| G4 | Подписка без электронного отказа / списание после удаления карты | ЗоЗПП ст. 16.1 в ред. 376-ФЗ (с 01.03.2026) | «списание после отказа», «отвязал карту», «не обеспечен приём отказа в электронной форме» |
| G5 | Отмена услуги только по телефону | ЗоЗПП ст. 16, 32; ГК 782 | «отказ от услуги только по телефону», «усложнение порядка отказа», «горячая линия» |
| G6 | Таймер + «осталось N шт.» + «№ 1» без источника | 38-ФЗ ст. 5 ч. 2 п. 1, ч. 3 п. 1 и 4; ФАС | «№ 1», «лучший», «первый», «некорректное сравнение», «ограниченное время», «не представлено подтверждение» |

Запрос составляется как: `<формулировка из таблицы> + <норма> + <тип акта>`.
Пример: `"автоматически проставлялась отметка" страхование "ст. 16" решение суда`.
Варьировать 3–5 формулировок на сценарий, фиксировать каждый запрос в журнале прогона.

3. База решений ФАС `br.fas.gov.ru` и сайты региональных УФАС — решения и предписания
   по 38-ФЗ (сценарии G3, G6).
4. ГИС ЗПП `zpp.rospotrebnadzor.ru`, раздел судебной практики — подборки с реквизитами.
5. Обзоры практики Верховного Суда `vsrf.ru`.

Наводки (только в `leads/`):
5a. Реестр практики из таблицы оператора `practice/cases.tsv` (190 строк, 13.10.2026; дайджесты `practice/sections/`, сводка `references/practice-registry.md`) — стартовый список дел по каждому сценарию и разделу; строки — наводки, первичку искать по ссылкам и на порталах из пп. 1–5.
6. Пресс-релизы `rospotrebnadzor.ru`, `fas.gov.ru/news`, региональных управлений.
7. Агрегаторы: `sudact.ru`, дайджесты вроде `sovetreklama.org`, юридические блоги.
8. Жалобы со скриншотами: vc.ru/claim, pikabu, banki.ru — только как указание на сайт
   и дату, не как источник.

Доступность порталов проверять в начале прогона; часть из них работает только
с российского IP или требует JS — тогда открывать через Chrome, а не через WebFetch.

Известные стартовые наводки (проверить, найти первичку):

  Управление Роспотребнадзора по Астраханской области, спор с 2023 г. (G1).
- «ИрАэро»: суд запретил навязывание, май 2024; автосогласие на страхование и платное
  кресло по умолчанию (G1).
- S7: сообщение Mash о страховке, спрятанной в общую галочку, — только наводка, акт не
  найден (G1).
- Кировское УФАС, апрель 2026: реклама «Первый маркетплейс для бизнеса» признана
  ненадлежащей (G6, часть «№ 1»).

## 3. Структура папок и форматы

```
evidence/
  CLAUDE.md
  enforcement/<ГГГГ>-<орган>-<номер-дела>/
      source.pdf              # первичный документ (скачанный PDF или Печать→PDF страницы)
      source.sha256
      source.url.txt          # точный URL, откуда взят, и UTC-время сохранения
      meta.yml                # см. §4
      quotes.md               # дословные цитаты с номером страницы, сверенные с текстовым слоем
  leads/<сценарий>/<ГГГГММДД>-<домен>.md   # наводки: что, где, дата публикации, URL (ручные)
  leads/<сценарий>/<ГГГГММДД>-<домен>-P-NNN.md  # наводки из таблицы практики, генерирует build_practice_leads.py — см. leads/README.md
  practice/                                # реестр практики из таблицы оператора: source/ (xlsx + sha256),
      cases.tsv · not-found.tsv            #   cards/<дело>/ (снимки карточек судов), sections/ (дайджесты) — см. practice/README.md
  captures/<сценарий>-<домен>-<ГГГГММДД>[-2]/
      NN-<шаг>.png            # скриншот агента
      NN-<шаг>.pdf            # Печать→PDF, делает Виталий
      session.gif
      capture-log.json        # см. §6
      manifest-draft.md       # поля для разметки Виталием, агент оставляет пустыми
  runs/<ГГГГММДД>-<сценарий>-<фаза>.md    # журнал прогона
```

Проверка текстового слоя обязательна для каждого PDF:
`pdffonts source.pdf` должен показать шрифты; `pdftotext source.pdf - | head` — читаемый
русский текст. Если слоя нет — файл переименовать в `source.scan.pdf`, в meta.yml
поставить `text_layer: false`, цитаты из него не брать.

## 4. meta.yml — реестр решения

Заполнять только из `source.pdf`. Каждое значение сопровождается страницей.

```yaml
id: 2025-mosgorsud-33-XXXXX          # год-орган-номер; номер строго как в документе
scenario: [G1]                       # коды из §1, может быть несколько
act_type: решение суда | постановление | решение УФАС | предписание
authority: Московский городской суд  # как в документе
case_number: "33-XXXXX/2025"         # как в документе, со всеми знаками
decision_date: 2025-00-00
respondent: ООО «Авиакомпания "Победа"»   # как в документе
applicant: Управление Роспотребнадзора по Астраханской области
norms_cited: ["ЗоЗПП ст. 16 п. 2"]   # только те, что названы в тексте
sanction: Не установлено по приложенным источникам   # сумма/предписание, со страницей
stage: Не установлено по приложенным источникам      # вступило в силу / обжалуется, со страницей
interface_facts:                     # что именно про экран написано в акте, дословно
  - page: 3
    quote: "..."
site_or_app: pobeda.aero             # если назван в акте; иначе Не установлено
source_url: https://...
source_sha256: ...
captured_utc: 2026-10-00T00:00:00Z
text_layer: true
notes: ""                            # расхождения, неясности — сюда, не в поля
```

Если какое-то поле в документе есть, но формулировка допускает двойное чтение —
значение + `notes`, а не выбор «наиболее вероятного».

## 5. Фазы прогона

**Фаза A — поиск решений (один сценарий).**
1. Проверить доступ к порталам из §2; записать, что открылось.
2. Прогнать 3–5 запросов, для каждого записать запрос и 0–10 первых релевантных карточек.
3. Для каждой карточки: открыть, убедиться, что это акт, а не новость. Скачать PDF или
   «Печать→PDF» страницы акта. Посчитать sha256, проверить текстовый слой.
4. Заполнить meta.yml и quotes.md по §4.
5. СТОП: показать Виталию список найденных актов (id, орган, дата, ответчик, сайт) и
   список наводок без первички. Спросить, какие сайты идут в фазу B.

**Фаза B — съёмка по решению (один сайт).**
1. Открыть сайт в Chrome, viewport 1440×900, русский интерфейс. Включить запись GIF.
2. Пройти тот маршрут, который описан в акте (`interface_facts`). Если акт маршрут не
   описывает — стандартный: главная → товар/услуга → корзина → шаги оформления до экрана
   перед оплатой.
3. На каждом шаге: скриншот на диск `NN-<шаг>.png`, запись в capture-log.json.
4. На ключевых экранах (тех, что упомянуты в акте, плюс первая цена и итоговая сумма):
   СТОП — попросить Виталия нажать Ctrl+P → «Сохранить как PDF» в ту же папку под тем же
   номером. Продолжать после «готово».
5. Для G6 — повторить маршрут через 15 минут и после перезагрузки страницы, отдельная
   папка с суффиксом `-2`. Для G1/G2 — попытаться снять галочку и зафиксировать реакцию.
6. Если флоу уже исправлен и паттерна нет — всё равно дописать серию до конца: это
   кандидат в clean-зеркало. Отметить в capture-log.json: `pattern_visible: unknown`
   (решает Виталий), в журнале — «паттерн из акта на экране не наблюдался».
7. Закрыть серию: sha256 всех файлов, manifest-draft.md с пустыми полями.

**Фаза C — отчёт.** `runs/<дата>-<сценарий>-<фаза>.md`: что искали, что нашли, что не
нашли и почему, что отложено, сколько первички и наводок добавлено, какие СТОПы были.

## 6. capture-log.json

```json
{
  "scenario": "G1",
  "site": "example.ru",
  "enforcement_ref": "2025-mosgorsud-33-XXXXX",
  "viewport": "1440x900",
  "locale": "ru-RU",
  "started_utc": "2026-10-00T00:00:00Z",
  "steps": [
    {
      "n": 1,
      "label": "главная",
      "url": "https://example.ru/",
      "utc": "2026-10-00T00:00:00Z",
      "title": "...",
      "files": {"png": "01-главная.png", "pdf": "01-главная.pdf"},
      "sha256": {"png": "...", "pdf": "..."},
      "agent_note": "что сделано на шаге, без оценок"
    }
  ],
  "pattern_visible": "unknown",
  "stops": ["02 — вход, пройден Виталием", "05 — Ctrl+P"]
}
```

`agent_note` — только действия и наблюдаемые факты («галочка «Страховка» отмечена при
загрузке»), без слов «навязывание», «нарушение», «тёмный паттерн».

## 8. Формулы запуска

- `Фаза A, сценарий G1` — только поиск и архивирование решений.
- `Фаза B, enforcement/2025-mosgorsud-33-XXXXX, сайт pobeda.aero` — съёмка по акту.
- `Фаза B, lead leads/G6/20260415-example.ru.md` — съёмка по наводке без акта
  (в manifest-draft «Источник-основание: нет»).
- `Фаза C` — отчёт по последнему прогону.

Любая другая формулировка — переспросить, какая фаза и какой сценарий.

## 9. Что считать неудачей прогона

- В meta.yml есть поле, не подтверждённое страницей source.pdf.
- Наводка попала в `enforcement/`.
- Серия без хотя бы одного PDF с текстовым слоем на ключевом экране.
- Пропущен СТОП перед входом, капчей или оплатой.
- В agent_note или журнале появились оценочные слова (нарушение, навязывание, обман).
