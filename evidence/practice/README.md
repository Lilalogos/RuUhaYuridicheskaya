# evidence/practice — реестр практики из таблицы оператора

Таблица «Судебная практика» (составлена 13.10.2026, передана Виталием 13.10.2026) — 190 строк судебной и административной практики по нормам для проектирования интерфейсов, 14 разделов, плюс лист «Практика не найдена» (23 нормы без дел). Здесь она хранится как **реестр наводок**: каждая строка говорит, где искать первичку, но сама первичкой не является.

## Дисциплина

- Строка таблицы = наводка (lead) в смысле `evidence/CLAUDE.md` §0.2, даже если в колонке «Источник сведений» стоит «текст акта или карточка суда»: документ открывал составитель таблицы, а не агент, и в архиве его нет.
- Поля отчёта, записи `enforcement_outcomes.yml` и капсулы из этих строк **не заполняются**. Путь в базу один: найти акт → `enforcement/<id>/` с source.pdf, sha256, meta.yml и quotes.md → `scripts/build_evidence_capsules.py`.
- Номера дел, даты и суммы в таблице нужно сверять с текстами актов (kad.arbitr.ru, сайты судов, br.fas.gov.ru) перед любым использованием.
- Снимки карточек (`cards/`) подтверждают реквизиты и стадию дела, но не содержат текста акта.

## Состав

| Файл | Что это |
|---|---|
| `source/sudebnaya-praktika-2026-10-13.xlsx` + `source.sha256` + `source.txt` | исходная таблица без изменений, контрольная сумма, происхождение |
| `cases.tsv` | лист «Все дела» (190 строк) + колонки `practice_id` (P-001…P-190), `norm_ids` (нормы базы, к которым строка привязана автоматически по колонке «Норма»), `scenario` (G1–G8 / content / consent / security / вне-охвата:*), `source_class` (act_or_card / news / search) |
| `practice.json` | то же в JSON (исходные колонки) |
| `not-found.tsv` | лист «Практика не найдена» |
| `cards/<папка>/` | снимки карточек Таганского районного суда Москвы по ст. 13.50 КоАП (`snapshot_card.py`): card.html, card.pdf с текстовым слоем, card.sha256, card.url.txt; индекс — `cards/INDEX.md` |
| `sections/NN-<slug>.md` | дайджест каждого раздела, строки целиком (производный) |

Сводный справочник — [`references/practice-registry.md`](../../references/practice-registry.md): покрытие по разделам, сценариям и нормам базы, нормы без записи в базе, лист «не найдено», пересечения с архивом актов. Всё производное пересобирается командой:

```bash
python3 -B scripts/import_practice_xlsx.py && python3 -B scripts/build_practice_registry.py
```

Привязка `norm_ids` и `scenario` — автоматическая, правила в `scripts/import_practice_xlsx.py` (пересоздаёт `cases.tsv`, `not-found.tsv`, `practice.json` из xlsx); строки без привязки — нормы, которых в базе нет (ИС, кадровый ЭДО, антимонопольное право, электронная подпись, УК). Целостность (sha256 таблицы и карточек) проверяет `scripts/evidence_check.py`.

## Как использовать

- **Фаза A** по сценарию: открыть `sections/` нужного раздела или отфильтровать `cases.tsv` по `scenario`, идти по ссылкам, искать акт на официальном портале, архивировать по регламенту.
- **Режим 3** («какие дела есть по норме X»): таблица «Нормы базы, по которым есть наводки» в `references/practice-registry.md`; в ответе такие дела помечать как наводки без приложенного акта.
- **Пробелы**: лист «не найдено» и таблица «Нормы, названные в практике, но не заведённые в базе» — вход для `references/gaps.md`.
