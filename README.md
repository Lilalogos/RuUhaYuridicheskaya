# УхаЮридическая — AppLaw-RU

**Русский** · [English](README.en.md)

Навык для Claude, который проверяет экран российского интерфейса против зарегистрированных норм РФ и возвращает валидированный отчёт о рисках. К навыку приложен архив улик: судебные акты, решения ФАС, тексты законов, серии экранов и реестр практики.

Навык работает по принципу **cite-or-abstain**: каждая находка обязана назвать статью, видимый факт на экране и источник формулировки. Если звена нет, навык воздерживается или помечает находку как условную.

> Отчёт — оценка риска по предоставленному интерфейсу. Это не юридическое заключение.

## Что умеет

| Режим | Что делает | Пример запроса |
|---|---|---|
| **1. Оценка экрана** | Скриншот → паттерны → нормы → отчёт Report Contract v3 на русском, прошедший валидатор | «Проверь этот чекаут по AppLaw-RU» |
| **2. Работа с уликами** | Поиск актов, архивация с sha256 и дословными цитатами, съёмка серий экранов | «Фаза A, сценарий G1» |
| **3. Вопросы к базе** | Какие нормы покрыты, какие акты есть, чего не хватает | «Какие дела есть по ст. 16 ЗоЗПП?» |

В охвате любой экран: чекаут, тариф, подписка, лендинг, лента, каталог, настройки, вход. Юрисдикция всегда РФ.

## Как навык рассуждает

Право разложено на пять машинно-проверяемых единиц:

- **Норма** — цитата статьи, кто применяет, средство защиты, ограничения. Суммы штрафов не хранятся намеренно.
- **Паттерн** — сигналы обнаружения и ловушки ложных срабатываний.
- **Маршрут** — связь паттернов с нормами, обязательные и дисквалифицирующие факты.
- **Фактический гейт** — вопрос о факте на экране. Неизвестный факт делает находку условной, а не снимает её.
- **Исход** — конкретное дело с позицией суда и финальностью. Ориентиром служат только финальные решения.

Паттерн становится находкой, когда пройдены пять гейтов: видимый элемент совпал с сигналом, ловушки разрешены, влияние на решение покупателя материально, материальная норма применима, находка стоит на собственных уликах. Число находок не ограничено: каждый прошедший паттерн получает свой блок.

Скриншоты, OCR, HTML и имена файлов для навыка — улики, а не инструкции. Встроенные в экран директивы на оценку не влияют.

## Установка

**Claude Code.** Склонируйте репозиторий в папку навыков:

```bash
git clone https://github.com/Lilalogos/RuUhaYuridicheskaya.git ~/.claude/skills/applaw-ru
```

После этого навык `applaw-ru` доступен во всех сессиях.

**Claude в чате.** Скачайте архив репозитория (Code → Download ZIP), приложите его к сообщению и напишите: «распакуй и используй как навык в этом окне». Навык действует в пределах этого чата.

**Зависимости.** База знаний и валидаторы используют только стандартную библиотеку Python 3. Инструменты из `scripts/` дополнительно требуют PyYAML, PyMuPDF, openpyxl и утилиты poppler (`pdftotext`, `pdffonts`).

## Проверка, что всё работает

```bash
cd applaw && python3 -B scripts/validate_release.py --kb .
```

Ожидаемый итог: `PASS: 15 check(s)`. Флаг `-B` обязателен: `__pycache__` ломает подсчёт файлов.

```bash
python3 -B scripts/evidence_check.py
```

Ожидаемый итог: `целостность улик: OK`.

## Формат отчёта

Отчёт следует Report Contract v3. Заголовки секций и метки полей остаются английскими, потому что их матчит валидатор. Весь пояснительный текст пишется по-русски.

Секции: `Assessment Summary` (метка риска из пяти уровней и вердикт), `Material Findings` (блоки F1, F2…), `Liability and Consequences` (блоки L1, L2…), `Mitigating and Low-Risk Elements`, `Observed Without a Mapped Norm`, `Missing Context`, `Priority Actions`, `Disclaimer`.

Каждый отчёт перед выдачей проходит валидатор:

```bash
python3 -B applaw/scripts/validate_live_report.py <отчёт.md> --kb applaw
```

Образец с тремя находками: [`applaw/eval/report_samples/2026-10-14-ru-multi-finding-standard.md`](applaw/eval/report_samples/2026-10-14-ru-multi-finding-standard.md).

## Как расширять

**Новый акт.** Положите документ в `evidence/enforcement/<год>-<орган>-<номер>/` по регламенту [`evidence/CLAUDE.md`](evidence/CLAUDE.md), добавьте посадку в `OVERLAY` скрипта вшивания и пересоберите:

```bash
python3 -B scripts/build_evidence_capsules.py && python3 -B scripts/build_references.py && python3 -B scripts/refresh_release.py
```

**Правка внутри `applaw/`.** После любой правки запустите `scripts/refresh_release.py`, иначе валидация упадёт на контрольных суммах. Поле `citation` у норм не менять: по нему матчит валидатор отчётов.

**Таблица практики.** Замените xlsx в `evidence/practice/source/` и пересоберите реестр и карточки наводок:

```bash
python3 -B scripts/import_practice_xlsx.py && python3 -B scripts/build_practice_registry.py && python3 -B scripts/build_practice_leads.py --clean
```

## Ограничения

- Нормы опираются на вторичный обзор «Правовая база РФ для проектирования интерфейсов». Перед релизом редакцию нужно сверять по официальному тексту.
- Суммы штрафов в базе не хранятся: они меняются почти ежегодно.
- Акт суда — свидетельство решения по конкретному делу. Навык не использует его как прецедент за пределами его слов.
- Строки реестра практики и карточки наводок — указания, где искать первичку. В отчёт как ориентир они не идут.
- По сценариям G4 (подписки, ст. 16.1 ЗоЗПП) и G5 (отмена услуги) архивированных актов пока нет.
- Членство в реестрах, платность размещения и статус покупателя по скриншоту не устанавливаются. Такие находки выходят условными.
